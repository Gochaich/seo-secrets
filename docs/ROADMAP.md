# Переезд сайта агентства с Tilda на собственный код с ИИ-редактированием

> Рабочий план проекта. Этот файл — источник правды по стеку и решениям.
> Каждая новая ИИ-сессия читает его первым, чтобы не пересказывать контекст заново.

Дата: 17 августа 2026 · Репозиторий: `gochaich/seo-secrets` · Срок: 3–4 недели

---

## 0. Принятые решения

| Вопрос | Решение | Что из этого следует |
|---|---|---|
| CRM | Пока никакой | Лиды живут в Postgres + Telegram + дубль в Google Sheets. Слой отправки в CRM пишем сразу как отдельный модуль с вебхуком — подключение amoCRM или Битрикс24 позже займёт полдня и не потребует трогать форму. |
| Кто правит тексты | Решим позже | Стартуем на MDX в репозитории. Тексты держим отдельно от вёрстки (`content/`), чтобы прикрутить Sanity позже без переписывания страниц. |
| Языки | Русский сейчас, казахский потенциально позже | Русский — язык по умолчанию **без префикса** в URL (`/uslugi`), чтобы адреса с Tilda сохранились один в один. Казахский добавится на `/kk/`. Роутинг с `localePrefix: as-needed` закладываем на этапе 2, тексты сразу выносим в словари — потом не переразбирать страницы. |

## 1. Что строим

- **Сайт** — Next.js + Tailwind на Vercel. Код в GitHub, история версий, откат в один клик.
- **Способ работы** — Claude Code в браузере, подключённый к репозиторию. Все правки текстом
  в диалоговом окне, без редактора и терминала.
- **Заявки** — своя воронка: форма → проверка → база → Telegram → письмо клиенту → CRM.
- **ИИ на сайте** — ассистент-квалификатор + лид-магнит «экспресс-аудит сайта».

### Честно о цене решения

Tilda даёт визуальный редактор: двигаешь блок мышкой и сразу видишь результат. Здесь этого
не будет — правки идут через текстовое описание и превью-ссылку. Для большинства задач это
быстрее, но первые 2–3 дня будет непривычно.

## 2. Ежедневный рабочий цикл

1. **Задача.** Открываешь https://claude.ai/code, выбираешь репозиторий, пишешь текстом:
   «на главной замени блок с ценами на три тарифа, добавь кнопку "Обсудить проект"».
2. **Правка.** Claude создаёт ветку, меняет код, проверяет сборку, открывает pull request.
3. **Превью.** Vercel собирает копию сайта с правками и кидает ссылку в pull request.
   Это живой сайт — можно кликать, заполнять формы, смотреть с телефона.
4. **Итерации.** «Кнопка мелкая, отступ сверху больше» — комментарий в PR, превью пересобирается.
5. **Мерж.** Кнопка Merge (в том числе с телефона) → через ~40 секунд изменения на проде.
6. **Откат.** Любой прошлый деплой возвращается кнопкой Rollback в Vercel.

### `CLAUDE.md` — обязателен

В корне репозитория лежит инструкция для ИИ: фирменные цвета и шрифты, правила вёрстки, тон
текстов, структура компонентов, чего делать нельзя. Без неё через месяц на сайте будет пять
разных кнопок и четыре оттенка зелёного — типовая болезнь «вайбкодинга».

## 4. Воронка заявок

Все точки входа (форма, ИИ-чат, бронь созвона, клик по мессенджеру) пишут в один обработчик.

| Шаг | Что происходит |
|---|---|
| Вход | Форма / ИИ-чат / бронь созвона / мессенджер |
| Проверка | Zod + Turnstile + лимит по IP — отсекаем ботов до попадания в CRM |
| Запись | Строка в Postgres: имя, контакт, сайт клиента, задача, страница входа, utm, реферер, время |
| Сигнал | Сообщение в Telegram-чат команды с кнопкой «взять в работу» |
| Ответ | Письмо клиенту через Resend + ссылка на календарь |
| Таблица | Строка в Google Sheets — рабочий список лидов, пока нет CRM |
| CRM | Модуль готов, выключен переменной окружения. Включается, когда появится CRM |
| Аналитика | Событие в GA4 и Метрику — конверсия по источникам и посадочным |

**Правовой минимум:** чекбокс согласия на обработку персональных данных, страница политики
конфиденциальности, cookie-баннер при работе с ЕС. Без этого не запускаемся.

## 5. ИИ на сайте

### Ассистент-квалификатор

Виджет со знанием услуг, цен, кейсов и отраслевой специфики — всё в системном промпте,
отдельная база знаний не нужна (сайт небольшой). Отвечает на вопросы, а когда разговор
доходит до дела — собирает контакт и задачу и создаёт заявку через ту же воронку.
В чат команды приходит не «имя + телефон», а расшифровка: какой сайт, ниша, проблема, бюджет.

Ограничения ставим сразу: лимит сообщений на посетителя, потолок расходов, запрет обсуждать
всё, кроме услуг агентства.

### Экспресс-аудит сайта — главный вход

Посетитель вводит адрес своего сайта. За 30 секунд получает мини-разбор: скорость и Core Web
Vitals из PageSpeed API, метатеги и заголовки из краула главной, robots и sitemap, разметка
schema.org — ИИ превращает это в человеческий текст с приоритетами. Полный отчёт — на почту,
то есть в обмен на контакт.

Для SEO-агентства это сильнее любой формы «оставьте заявку»: отдаём реальную пользу, лид
приходит прогретым, его проблемы видны до первого созвона. На Tilda такое не собрать.

## 6. Переезд без потери позиций

Свой просевший сайт для SEO-агентства — прямой удар по продажам. Переезд по протоколу:

1. **До переезда.** Полный краул Tilda в Screaming Frog: все URL, title, description, H1,
   ссылки. Выгрузка Search Console за 16 месяцев: запросы и страницы входа. Точка отсчёта.
2. **Карта URL.** Адреса сохраняем один в один. Всё, что меняется, — в таблицу редиректов
   `301` в конфиге Next.js, сразу, а не «потом настроим».
3. **Тексты не трогаем.** Меняем оболочку, а не содержание. Переписывание текстов — отдельной
   задачей через 3–4 недели после стабилизации, иначе при просадке не понять причину.
4. **Метаданные.** title/description переносим как есть; schema.org — Organization, Service,
   FAQPage, BreadcrumbList, Article; sitemap.xml, robots.txt, canonical, Open Graph.
5. **Скорость.** Замер Core Web Vitals до и после — фиксируем выигрыш цифрами.
6. **Запуск.** DNS переключаем в низкий трафик, сразу отправляем sitemap в GSC и Вебмастер.
7. **Первые 4 недели.** Ежедневно отчёт «Покрытие» и показы в GSC, 404 в логах Vercel.

**Tilda не отключаем сразу** — держим оплаченной ещё месяц. DNS возвращается за 10 минут.

## 7. Поэтапный план

Сроки — при работе в полноценном режиме. Порядок менять нельзя: каждый этап опирается
на предыдущий.

### Этап 1 — Аудит и подготовка · 2–3 дня
- Краул текущего сайта, выгрузка всех URL и метатегов
- Выгрузка Search Console, фиксация текущих позиций и трафика
- Экспорт текстов и картинок с Tilda, сбор структуры страниц
- Фиксация списка URL, которые обязаны сохраниться один в один

**Результат:** таблица «страница → URL → title → H1 → трафик» и утверждённая карта сайта.

### Этап 2 — Инфраструктура · 1 день
- Next.js + TypeScript + Tailwind в репозитории, подключение Vercel
- Тестовый домен, автодеплой, превью на pull request
- Хранилище секретов, заготовки переменных окружения
- Роутинг next-intl: русский без префикса, задел под `/kk/`
- Тексты выносим в `content/` — задел под CMS
- `CLAUDE.md` с правилами проекта

**Результат:** первая задача в чат → рабочая превью-ссылка. Цикл налажен.

### Этап 3 — Дизайн-система · 2–3 дня
- Цвета, шрифты, отступы, состояния как токены, а не в разметке
- Библиотека блоков: герой, услуги, кейсы, цены, отзывы, FAQ, CTA, футер
- Мобильная версия как основной сценарий

**Результат:** новая страница собирается за 15 минут одной фразой в чат.

### Этап 4 — Сборка страниц · 3–5 дней
- Главная, услуги, кейсы, о команде, контакты, блог
- Перенос текстов один в один, без переписывания
- Картинки в WebP/AVIF через встроенную оптимизацию

**Результат:** сайт целиком на тестовом домене, готов к сверке со старым.

### Этап 5 — Воронка заявок · 2 дня
- Обработчик формы, валидация, антиспам, лимиты
- База, Telegram-бот, письмо клиенту, дубль в Google Sheets
- Модуль отправки в CRM — написан, выключен до появления CRM
- Встроенная бронь созвона, события в GA4 и Метрику
- Тестовые прогоны, в том числе сценарий «внешний сервис недоступен»

**Результат:** заявка доходит по всем каналам, ничего не теряется при сбое любого из них.

### Этап 6 — ИИ-ассистент и экспресс-аудит · 3–4 дня
- Виджет чата со знанием услуг и кейсов, создание заявки из диалога
- Лимиты, потолок расходов, защита от увода темы
- Инструмент аудита: PageSpeed + разбор метатегов + отчёт на почту

**Результат:** два канала лидов, которых на Tilda не было.

### Этап 7 — Техническое SEO и правовая часть · 2 дня
- Метатеги, schema.org, sitemap, robots, canonical, Open Graph
- Таблица 301-редиректов, проверка каждого
- Политика конфиденциальности, согласие на обработку данных, cookie-баннер
- Финальный краул нового сайта и сверка с таблицей из этапа 1

**Результат:** ни одного URL из старого списка без адреса на новом сайте.

### Этап 8 — Запуск и стабилизация · 1 день + месяц наблюдения
- Переключение DNS, отправка sitemap в GSC и Вебмастер
- Проверка форм на боевом домене, контрольная заявка
- Ежедневный контроль индексации и 404 первые 2 недели
- Tilda оплачена ещё месяц как страховка

**Результат:** сайт на новом стеке, позиции на месте, дальше цикл «задача → превью → мерж».

## 9. Что нужно, чтобы начать

Решения по CRM, CMS и языкам приняты — см. раздел 0. Осталось собрать входные данные:

1. **Адрес текущего сайта на Tilda** — без него не снять точку отсчёта и не собрать карту URL.
2. **Доступ в Google Search Console** — выгрузка запросов и страниц входа за 16 месяцев.
3. **Доступы:** Vercel, регистратор домена или Cloudflare, Telegram (создать бота через
   @BotFather), Google-аккаунт для таблицы лидов.

Этапы 2 и 3 — инфраструктура и дизайн-система — не зависят ни от одного из этих пунктов
и могут стартовать сразу.

## Как агент видит текущий сайт

У среды агента нет выхода в интернет: `seo-secrets.kz`, CDN Тильды и прочие
внешние адреса закрыты политикой сети. Поэтому всё, что нужно из сети,
делается через GitHub Actions — там интернет есть.
